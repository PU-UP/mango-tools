# 修复与恢复说明

已在修改前备份原始可用版本：`backups/before-fixes-20260831-172022/`。
备份包含原始 `client.py`、`server.py` 和 `SHA256.txt`；修复后再次校验，备份内容未变。

## 使用新版

Windows 下可直接双击项目目录中的 `启动客户端.bat` 打开客户端；也可以右键为它创建桌面快捷方式。启动入口会切换到程序所在目录，优先使用无控制台窗口的 Python 启动器。电脑仍需安装带 Tkinter 的 Python 3。

原来的命令行启动方式继续可用，不需要安装新依赖。关闭旧的客户端和服务端进程，再按原有参数启动。
两端都更新才能获得完整修复；已验证旧客户端仍可以向新版服务端进行普通上传。

修复内容：

- 下载先写同目录临时文件，检查 Content-Length 后替换目标；传输失败时保留原文件并清理临时文件。
- 上传使用 URL 指定的目录，缺少的子目录会自动创建；拒绝越出共享根目录的路径。
- 下载路径解码后必须位于所选保存目录内。
- 修正浏览器目录页的 Content-Length，保留上传表单。
- 使用标准库解析 multipart，正确处理中文、分号文件名与二进制内容；不完整上传返回错误。
- 修正 Windows/Linux 子网识别。为保持扫描有界，大于 /24 的网络只扫描本机所在 /24，最多 254 个地址；其他地址可手动输入。
- 空文件夹或目录扫描失败后恢复按钮状态；相关界面更新与提示切回主线程。

同名文件仍按原来的方式覆盖，但文件下载完整或上传临时文件写好之后才替换目标。
批量上传不保证整个批次原子提交：若后面的文件保存失败，之前成功保存的文件会保留。
上传仍整包读入内存，大文件或多文件批量上传可能占用较多内存。
没有加入身份验证或加密，仍只适合可信局域网。没有 Content-Length 的下载无法仅凭长度判断远端是否提前结束。

## 恢复旧版

1. 关闭客户端和服务端程序。
2. 从 `backups/before-fixes-20260831-172022/` 复制 `client.py` 和 `server.py`，覆盖项目根目录中的同名文件。
3. 按之前的启动方式重新运行。备份目录中的两个文件不要编辑，保持它们作为原始版本。

恢复操作只替换程序，不需要删除已经传输的文件。
